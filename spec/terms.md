# Terms

## Primitive contracts

- **capability-app** — the capability case app's source inputs, as data a proof writes into a temporary project.
  - Role: fact
  - Zone: core
  - Of: []
- **case-inventory** — the independently supplied identities, conditions and input paths of the structural fixture cases.
  - Role: fact
  - Zone: core
  - Of: []
- **claim** — a promise declared once in its topic and proved by tests.
  - Role: fact
  - Zone: core
  - Of: []
- **code-token** — one piece of a file's code, in source order: a token or a comment, with its range in the text and whether a line break comes before it since the last token.
  - Role: fact
  - Zone: core
  - Of: []
- **command** — what a launcher hands a Kit command and what the command answers.
  - Role: fact
  - Zone: core
  - Of: []
- **comment** — supplied implementation text and its source location; it explains choices that other artifacts do not express.
  - Role: fact
  - Zone: core
  - Of: []
- **compiler-facts** — plain compiler observations about projects, settings, types, imports and authority entries supplied to the checks.
  - Role: fact
  - Zone: core
  - Of: []
- **default-config** — the target layout, as the config an app starts from.
  - Role: fact
  - Zone: core
  - Of: []
- **exported-symbol** — a supplied exported name and its declaring file.
  - Role: fact
  - Zone: core
  - Of: []
- **file** — a supplied file in a snapshot, identified by its path.
  - Role: fact
  - Zone: core
  - Of: []
- **file-facts** — one file's share of its project's compiler facts, and one test's reach with the files it was read from, as stored under the key of what they depend on.
  - Role: fact
  - Zone: core
  - Of: {{compiler-facts}}, {{file}}
- **function-span** — one function no other function holds: the range of its body in the file's text and the lines it spans.
  - Role: fact
  - Zone: core
  - Of: []
- **ignored-import** — the error for an import into a path the config ignores.
  - Role: derived
  - Zone: core
  - From: []
- **import** — a supplied relation from an importing file to the file it imports.
  - Role: fact
  - Zone: core
  - Of: []
- **layer** — a declared dependency position and its permitted import relationships.
  - Role: fact
  - Zone: core
  - Of: []
- **program-scope** — what every fact reader over one compiler program shares: the program, its checker, the checked sources and the app-relative path of a file.
  - Role: fact
  - Zone: substrate
  - Of: {{default-config}}
- **reference** — a marked use that points to the home of a term, topic or claim.
  - Role: fact
  - Zone: core
  - Of: []
- **runs** — what each test ran, from the passes `kit verify` kept that still hold: the named functions of each placed module it ran.
  - Role: fact
  - Zone: core
  - Of: []
- **small-app** — the small app the extraction and ignore proofs write into a temporary project, and what its config ignores.
  - Role: fact
  - Zone: core
  - Of: []
- **snapshot** — the supplied files, declarations, configuration and compiler facts of one codebase.
  - Role: fact
  - Zone: core
  - Of: {{claim}}, {{comment}}, {{compiler-facts}}, {{default-config}}, {{exported-symbol}}, {{file}}, {{import}}, {{reference}}, {{runs}}, {{term}}
- **term** — a concept defined once in the global terms file, with its meaning and any declared contract metadata.
  - Role: fact
  - Zone: core
  - Of: []
- **topic** — the unit the maintainer ratifies and the agent works from; it explains why its modules exist and how they compose.
  - Role: fact
  - Zone: core
  - Of: []
- **verdict** — a check that passed, with the state of every path inside the app its run read, how long it took, and for a test, what it ran.
  - Role: fact
  - Zone: core
  - Of: []
- **zone** — what code may do: core, shell or substrate.
  - Role: fact
  - Zone: core
  - Of: []

## Reading contracts

- **access-authority** — what a module's own member accesses acquire: native roots, and clock or randomness samples only its adapter may take.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **authority-graph** — what each checked file acquires from its own code and inherits through runtime imports.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **baseline-files** — a baseline kept as one file per finding path: the file a path's keys live in, the record the files make together, and the files a record is kept as.
  - Role: derived
  - Zone: core
  - From: []
- **batch-attribution** — which test of one runner invocation over several test files each recording, use and result belongs to, and the tests whose attribution is unclear and run again alone.
  - Role: derived
  - Zone: core
  - From: {{verdict-reuse}}
- **behaviour-check** — the check that the core and readings take data or registered contracts, never other behaviour.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **binding-findings** — findings from comparing claim homes, executable proofs and named modules in a supplied snapshot.
  - Role: derived
  - Zone: core
  - From: {{claim-proof-binder}}, {{finding}}, {{module-references}}, {{snapshot}}
- **capability-context** — what every capability check reads: checked files, declared entrypoints, adapter contracts and native roots, and how a capability finding is categorised.
  - Role: derived
  - Zone: core
  - From: {{compiler-facts}}, {{default-config}}, {{finding}}, {{layer}}, {{placement-of}}, {{snapshot}}
- **check-paths** — the root, config and baseline paths a check is given, resolved against where the caller runs.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **claim-cohesion** — the check that the claims naming a module share the code of it their tests use.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{proof-reach}}, {{snapshot}}
- **claim-inventory** — claim declarations, module relationships and references interpreted from supplied Markdown.
  - Role: derived
  - Zone: core
  - From: {{claim}}
- **claim-proof-binder** — findings from matching claim declarations and topic-first test names.
  - Role: derived
  - Zone: core
  - From: {{snapshot}}, {{finding}}, {{placement-of}}
- **claim-runs** — what each claim's tests ran of each placed module, beside the claims that name it.
  - Role: derived
  - Zone: core
  - From: {{claim-proof-binder}}, {{compiler-facts}}, {{placement-of}}, {{proof-reach}}, {{runs}}, {{snapshot}}
- **comment-check** — the check that comments cite nothing and carry no debt.
  - Role: derived
  - Zone: core
  - From: {{zone}}, {{claim-proof-binder}}, {{finding}}, {{placement-of}}, {{layer}}, {{snapshot}}
- **compiler-check** — the check that checked files are compiled strictly, without errors or escape hatches.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **config-schema** — the keys a Kit configuration may declare at each level, and the keys a declaration holds that Kit doesn't read, each named by its full path.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **config-values** — the values a Kit configuration declares, checked as they are read: mappings, text, zones and relative locations.
  - Role: derived
  - Zone: core
  - From: {{default-config}}
- **construction-check** — the check that only an adapter builds its contract's values and only a declared core producer its write descriptions.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **consumer-report** — what one app check reports for that app: its failures by check beside the Kit commit it pins.
  - Role: derived
  - Zone: core
  - From: []
- **coverage-report** — the named functions an LCOV report lists for each file, by start line, and how often each ran, and the start line of every function it shows ran.
  - Role: derived
  - Zone: core
  - From: []
- **dependency-check** — findings from import direction and cycles between placed modules.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **dependency-exclusions** — findings and limits from the explicit separations an app declares between selected code.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **edge-check** — findings from import edges among checked code: entrypoint imports, layer and zone direction, legacy edges and cycles.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{dependency-check}}, {{snapshot}}
- **excerpt-cohesion** — debt from a module holding the excerpts of two or more claims: code only one claim runs, held by no code others run.
  - Role: derived
  - Zone: core
  - From: {{claim-runs}}, {{finding}}, {{placement-of}}, {{runs}}, {{snapshot}}
- **fact-keys** — the key one project's facts answer to, and for each file the files its imports reach and the key of all of them.
  - Role: derived
  - Zone: core
  - From: []
- **finding** — what a check reports: its rule, a path, the fix and a debt key.
  - Role: derived
  - Zone: core
  - From: []
- **fixture-config** — the adapter boundaries of the structural fixture derived by extending the default configuration.
  - Role: derived
  - Zone: core
  - From: {{default-config}}
- **fixture-files** — the files of a compiler fixture: a strict project over the declared roots, with the given sources.
  - Role: derived
  - Zone: core
  - From: {{default-config}}
- **fixture-snapshot** — a headless snapshot derived from supplied case descriptions for structural proofs.
  - Role: derived
  - Zone: core
  - From: {{comment}}, {{default-config}}, {{exported-symbol}}, {{file}}, {{import}}, {{snapshot}}, {{term}}
- **forwarder-check** — findings for each module that only re-exports other modules and defines nothing of its own.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **function-governance** — debt from the named functions of a module that no claim naming it runs.
  - Role: derived
  - Zone: core
  - From: {{claim-runs}}, {{finding}}, {{runs}}, {{snapshot}}
- **function-size** — findings for each named function whose body spans more lines than the configured limit, carrying its lines.
  - Role: derived
  - Zone: core
  - From: {{compiler-facts}}, {{finding}}, {{placement-of}}, {{snapshot}}
- **global-authority** — what a module acquires through ambient globals, and which uses need a declared adapter.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **handover-check** — findings where code outside the zones hands placed code behaviour that is no adapter contract.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **import-authority** — what a module acquires by importing outside the checked code: adapter packages, entrypoint packages and declared package rows.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **layout-check** — findings from comparing file roles with configured target roots and existing legacy locations.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **layout-configuration** — the layout an app opts into: its existing legacy locations.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **legacy-size** — the size of each legacy module as debt: its statements, and how many of them only call into placed modules.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{snapshot}}
- **legacy-zone-configuration** — the zones legacy code is declared in, by root or by exact files.
  - Role: derived
  - Zone: core
  - From: {{config-values}}, {{default-config}}
- **limit-configuration** — the size limits an app opts into: the most lines a named function's body may span.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **line-ratchet** — whether a legacy function's lines exceed what its baseline records, and the smaller of the two that the baseline keeps.
  - Role: derived
  - Zone: core
  - From: {{finding}}
- **module-references** — the check that every placed module is named by a claim it keeps, and the claims each module keeps.
  - Role: derived
  - Zone: core
  - From: {{snapshot}}, {{finding}}, {{placement-of}}
- **name-check** — the check of unique global term definitions and retired words in names, prose and comments.
  - Role: derived
  - Zone: core
  - From: {{claim-proof-binder}}, {{finding}}, {{placement-of}}, {{snapshot}}
- **paid-debt** — the baseline entries whose debt is paid: keys no legacy or proof debt finding holds, legacy sizes larger than the module now is and legacy function lines more than the function now spans, each with its fix and the reason its entry carries.
  - Role: derived
  - Zone: core
  - From: {{line-ratchet}}, {{ratchet}}
- **placement-of** — the interpretation of a supplied path and root as declared placement, legacy code, a claim proof or an entrypoint.
  - Role: derived
  - Zone: core
  - From: {{layer}}, {{zone}}
- **project-snapshot** — a snapshot of one strict compiler project holding only the given facts, for a check proved on what it reads.
  - Role: derived
  - Zone: core
  - From: {{compiler-facts}}, {{default-config}}, {{snapshot}}
- **proof-reach** — the check that a claim's tests together reach, through the code they use, every placed module the claim names.
  - Role: derived
  - Zone: core
  - From: {{claim-proof-binder}}, {{finding}}, {{placement-of}}, {{snapshot}}
- **proof-scope** — debt from the placed modules a claim's tests reach without the claim naming them; a named composition, or a named module under the proof root, names what it reaches.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{placement-of}}, {{proof-reach}}, {{snapshot}}
- **ran-code** — the outermost functions a run ran, by where the functions its coverage shows ran start, and a loaded file's code with the bodies of the rest left out, as the state a pass keeps.
  - Role: derived
  - Zone: core
  - From: {{code-token}}, {{fact-keys}}, {{function-span}}
- **ratchet** — the findings that fail a change: placed violations, reachable limits, new debt and grown legacy, with a proof's findings as its debt, and the baseline left after a change lands.
  - Role: derived
  - Zone: core
  - From: {{default-config}}, {{finding}}, {{line-ratchet}}
- **refs-description** — the claims that name a module, with their text and tests, and how they are listed.
  - Role: derived
  - Zone: core
  - From: {{claim-inventory}}, {{default-config}}, {{module-references}}, {{placement-of}}
- **registration-check** — the check that adapter registrations resolve and legacy zone rows list existing legacy files.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}
- **relative-import** — the known file a relative import names when no compiler project resolves it.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **root-token** — how the app root is written inside stored text, so worktrees of one repository share it.
  - Role: derived
  - Zone: core
  - From: []
- **semantic-references** — marked topic and term references, their resolved homes, incoming topic relationships and nonexclusive module groups.
  - Role: derived
  - Zone: core
  - From: {{reference}}, {{topic}}, {{finding}}, {{snapshot}}
- **shared-passes** — where passes are shared on `origin`: the refs a run reads and the one it adds to, the path of a pass in their trees, which shared entries are passes, and what a ref lacks.
  - Role: derived
  - Zone: core
  - From: {{verdict-reuse}}
- **snapshot-comparison** — whether two snapshots are the same graph.
  - Role: derived
  - Zone: core
  - From: []
- **startup-check** — the check that each declared entrypoint is an exact existing file outside every zone, and that entrypoint package contracts are well formed.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{finding}}, {{placement-of}}, {{snapshot}}
- **term-inventory** — global term definitions and inline declarations interpreted from supplied Markdown, with retained prose and syntax findings.
  - Role: derived
  - Zone: core
  - From: {{term}}
- **term-model** — findings and explicit limits from comparing declared roles, direct dependencies and selected named field types with source evidence.
  - Role: derived
  - Zone: core
  - From: {{snapshot}}, {{term}}, {{finding}}, {{placement-of}}
- **term-order** — the check that each list in the terms file is in alphabetical order.
  - Role: derived
  - Zone: core
  - From: {{finding}}, {{snapshot}}
- **test-groups** — the group each test runs in: the first whose directories hold it and whose modules, named or registered with a capability it names, its imports reach, else the first such group that names neither.
  - Role: derived
  - Zone: core
  - From: {{default-config}}, {{import}}, {{placement-of}}
- **test-roots** — the directories a test runner discovers: the proof root and the legacy test roots an app declares.
  - Role: derived
  - Zone: core
  - From: {{config-values}}
- **test-runs** — what each test ran, from its coverage reports: the named functions of each placed module.
  - Role: derived
  - Zone: core
  - From: {{compiler-facts}}, {{coverage-report}}, {{default-config}}, {{file}}, {{placement-of}}
- **topic-shape** — the check that a topic is a title, a short intro, then only section headings and claims with optional module relationships.
  - Role: derived
  - Zone: core
  - From: {{snapshot}}, {{finding}}, {{claim-inventory}}
- **verdict-reuse** — how a check's processes used each path, the paths a process other than the test's loaded, the key each path is kept under and what it holds, a stored verdict read back, where a check's passes are kept, the kept entry whose paths all still hold, where an entry is kept among its subject's, and what each test ran from its pass that still holds.
  - Role: derived
  - Zone: core
  - From: {{fact-keys}}, {{runs}}, {{verdict}}
- **verification-configuration** — the gate an app declares under `verify`, checked as it is read.
  - Role: derived
  - Zone: core
  - From: {{config-values}}, {{default-config}}
- **zone-authority-check** — the check that what each module, entrypoint and legacy edge holds is permitted where it is.
  - Role: derived
  - Zone: core
  - From: {{authority-graph}}, {{capability-context}}, {{snapshot}}, {{zone-permission}}
- **zone-permission** — whether code at a path may hold a capability, by its zone and the adapters registered for it.
  - Role: derived
  - Zone: core
  - From: {{capability-context}}, {{snapshot}}


## Adapter contracts

- **calendar** — access to the wall-clock time, which names the day a shared pass is published under.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **compiler** — access to project loading, with the text of every compiler config it read, import resolution and a file's outermost functions and significant code through a language compiler.
  - Role: adapter
  - Zone: substrate
  - Of: {{code-token}}, {{function-span}}
- **coverage-provider** — a vitest 1.x coverage provider that writes each test file's result, coverage and executed scripts apart.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **evidence-store** — ownership of what a machine learns about an app between runs: one file per key beside the repository, read and written whole, and evicted least recently used past a limit.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **filesystem** — access to file text, directory entries, the state a path is in, its kind, when it last changed, and the version it is in.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **git-refs** — access to refs on a repository's `origin`: a ref's tip and the files of its tree, a commit added on a tip pushed without force, and the clone's copies of other refs forgotten.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **processes** — access to running another program to completion, and to the environment the programs it runs inherit.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **read-recorder** — a preload that records every path inside the app a check's processes read, list, probe or load, with how each was used.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **source-loader** — access to Kit's TypeScript modules from a JavaScript launcher.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **stopwatch** — access to the time, for receipts.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **temporary-project** — ownership of an isolated temporary directory, its fixture file writes, its links and its disposal.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **terminal-input** — access to what a command was given on its standard input.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **text-files** — access to plain text files outside a snapshot: configs, baselines and spec listings.
  - Role: adapter
  - Zone: substrate
  - Of: []
- **toolchain** — access to the identity of the Kit that reads an app, from its own source, and when it reads the app from outside it, and of the runtime, installed packages and package manifest a check runs on.
  - Role: adapter
  - Zone: substrate
  - Of: []

## Composition contracts

- **authority-recorder** — the recorder of where a file's code can acquire authority: export parameters, raw primitives, dynamic code, native members and ambient globals.
  - Role: composition
  - Zone: substrate
  - Of: {{behaviour-reading}}, {{compiler-facts}}, {{file-scope}}, {{native-reading}}, {{program-scope}}, {{syntax-reading}}
- **behaviour-reading** — the reading of whether a type is or accepts behaviour: callable, an accessor, or an object with operations that is not a registered contract.
  - Role: composition
  - Zone: substrate
  - Of: {{contract-reading}}, {{native-reading}}, {{placement-of}}, {{program-scope}}
- **capability-check** — every authority rule over one snapshot, and what each checked file directly and transitively requires.
  - Role: composition
  - Zone: core
  - Of: {{access-authority}}, {{authority-graph}}, {{behaviour-check}}, {{capability-context}}, {{compiler-check}}, {{construction-check}}, {{edge-check}}, {{finding}}, {{global-authority}}, {{import-authority}}, {{registration-check}}, {{snapshot}}, {{startup-check}}, {{zone-authority-check}}
- **check-run** — the `kit check` workflow: read the governed root, run the gate and fail on what the baseline doesn't hold and on what it holds that is paid.
  - Role: composition
  - Zone: substrate
  - Of: {{baseline-files}}, {{check-paths}}, {{command}}, {{evidence-store}}, {{gate}}, {{held-state}}, {{paid-debt}}, {{ratchet}}, {{read-config}}, {{read-snapshot}}, {{stopwatch}}, {{test-groups}}, {{text-files}}, {{toolchain}}, {{verdict-reuse}}, {{verification-configuration}}
- **configuration-runner** — the workflow that loads the configuration readers once for an app's scripts that run under plain Node.
  - Role: composition
  - Zone: substrate
  - Of: {{source-loader}}
- **consumers-run** — the `kit consumers` workflow: check each app checkout against this Kit and report its work.
  - Role: composition
  - Zone: substrate
  - Of: {{command}}, {{config-values}}, {{consumer-report}}, {{kit-configuration}}, {{processes}}, {{text-files}}
- **contract-reading** — the reading of the identities a type names in the checked sources: its contract, the ports its operations return and its named parts.
  - Role: composition
  - Zone: substrate
  - Of: {{program-scope}}
- **contract-recorder** — the recorder of the contracts a file declares and the values of a named type it constructs.
  - Role: composition
  - Zone: substrate
  - Of: {{behaviour-reading}}, {{compiler-facts}}, {{contract-reading}}, {{file-scope}}, {{native-reading}}, {{program-scope}}
- **escape-recorder** — the recorder of the escape hatches in a file: `any`, type and non-null assertions, and compiler directive comments.
  - Role: composition
  - Zone: substrate
  - Of: {{compiler-facts}}, {{file-scope}}
- **extraction-proof** — the workflow that writes the small app into a temporary project, reads it through a store of its own, edits it, and reports what each read reused beside a read without the store.
  - Role: composition
  - Zone: substrate
  - Of: {{default-config}}, {{evidence-store}}, {{read-snapshot}}, {{small-app}}, {{snapshot}}, {{temporary-project}}
- **fact-walk** — the one walk over a program's checked sources that hands every node to each recorder it is given.
  - Role: composition
  - Zone: substrate
  - Of: {{file-scope}}, {{program-scope}}
- **file-scope** — one checked source file as its recorders see it: its path and the stable site key of a node there.
  - Role: composition
  - Zone: substrate
  - Of: []
- **forward-reading** — the reading of the module specifiers a source file only forwards, when it defines nothing of its own.
  - Role: composition
  - Zone: substrate
  - Of: []
- **function-recorder** — the recorder of each source's named functions: the name a runtime reports, its line, a stable id, the function holding it and the lines its body spans.
  - Role: composition
  - Zone: substrate
  - Of: {{compiler-facts}}, {{file-scope}}
- **gate** — the workflow that runs every rule on one snapshot and gathers what the ratchet judges.
  - Role: composition
  - Zone: core
  - Of: {{capability-check}}, {{claim-cohesion}}, {{claim-proof-binder}}, {{comment-check}}, {{default-config}}, {{dependency-exclusions}}, {{finding}}, {{forwarder-check}}, {{function-size}}, {{handover-check}}, {{layout-check}}, {{legacy-size}}, {{module-references}}, {{name-check}}, {{placement-of}}, {{proof-reach}}, {{proof-scope}}, {{excerpt-cohesion}}, {{function-governance}}, {{ratchet}}, {{semantic-references}}, {{snapshot}}, {{term-model}}, {{term-order}}, {{topic-shape}}
- **held-state** — what a kept key's path in the app holds now: its content, its kind, or its code as the functions a run ran see it, read once per version of the path within one run.
  - Role: composition
  - Zone: substrate
  - Of: {{compiler}}, {{filesystem}}, {{function-span}}, {{ran-code}}, {{text-files}}, {{verdict-reuse}}
- **import-recorder** — the recorder of where a file's imports lead and what each of its exports is.
  - Role: composition
  - Zone: substrate
  - Of: {{behaviour-reading}}, {{compiler-facts}}, {{contract-reading}}, {{file-scope}}, {{placement-of}}, {{program-scope}}, {{syntax-reading}}
- **kit-configuration** — the config an app declares, read from its YAML fence and validated section by section, and the paths a check is given.
  - Role: composition
  - Zone: core
  - Of: {{config-schema}}, {{config-values}}, {{default-config}}, {{layout-configuration}}, {{legacy-zone-configuration}}, {{limit-configuration}}, {{verification-configuration}}
- **native-reading** — the reading of the host authority a type or member reaches: its native root, its bases, and whether only a window host has it.
  - Role: composition
  - Zone: substrate
  - Of: {{compiler-facts}}, {{program-scope}}
- **pass-sharing** — the workflow that keeps the passes on `origin`'s shared refs in the local store, and adds a run's passes to today's ref, again on a moved tip.
  - Role: composition
  - Zone: substrate
  - Of: {{evidence-store}}, {{git-refs}}, {{shared-passes}}
- **program-fixture** — the workflow that compiles a fixture and hands a test its program scope, so a proof uses only the recorders it names.
  - Role: composition
  - Zone: substrate
  - Of: {{compiler}}, {{default-config}}, {{fixture-files}}, {{program-scope}}, {{temporary-project}}
- **project-facts** — the workflow that reads one compiler project's facts, reusing each file's and test's stored facts while their key matches and walking only the rest.

## Supporting vocabulary and roles

- **capability** — access to an operation a module may perform.
- **check** — a reading that reports findings for a rule.
- **config** — what an app declares to the kit.
- **core** — the zone that decides everything and performs no effect.
- **cycle** — a dependency path that returns to its starting module.
- **debt-key** — a finding's stable name, which a debt list holds.
- **file-type** — what a file is: source, test, spec or other.
- **heading** — the spec line that carries a module's identity.
- **import-edge** — one file's import of another.
- **inventory** — the collected declarations and references read from a document.
- **kit** — the checks, their spec and their config, applied to an app.
- **legacy** — a source file that is not placed.
- **maintainer** — the person who ratifies the spec and approves each change to the kit.
- **marker** — the notation identifying a declaration or reference.
- **module** — one named contract, at `<zone>/<layer>/<name>`, defined once in the terms file.
- **placed** — at `<zone>/<layer>/<name>`, and so held to the placement rules.
- **placement** — a module's declared zone, layer and name.
- **proof** — a test that establishes a claim.
- **prose** — any text of the spec.
- **public** — importable from another zone under the inward dependency rule.
- **read** — to take a snapshot of a codebase.
- **resolved** — matched to exactly one existing home in the intended namespace.
- **result** — the value returned by a reading or composition.
- **rule** — one of R1–R4; every check serves one.
- **semantic** — identifying a defined meaning rather than matching an ordinary word.
- **spec** — the prose the maintainer ratifies.
- **statement** — one TypeScript statement, wherever it is nested; a block or an empty statement is not counted.
- **workspace** — the project files and settings a compiler loads.
